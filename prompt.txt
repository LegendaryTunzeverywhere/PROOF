# MASTER BUILD PROMPT

# PROOF — Learn It. Prove It. Earn It.

## 0. ROLE

You are a senior product engineer, full-stack TypeScript developer, AI engineer, Web3 engineer, product designer, UX designer, and startup CTO.

You are building a production-quality Nimiq Mini App for a competitive hackathon/mini-app competition.

The product is called:

# PROOF

### Learn it. Prove it. Earn it.

PROOF is an AI-powered skill-learning and skill-verification marketplace.

Users can learn virtually anything, complete practical challenges, prove their ability through projects/tests, earn NIM rewards, and eventually monetize their verified skills by completing real tasks or teaching others.

The application must feel like a polished startup/product, NOT a hackathon prototype.

The blockchain should power the economy without making the application feel like a crypto application.

---

# 1. PRODUCT THESIS

Traditional learning platforms optimize for:

WATCHING CONTENT
↓
COMPLETING LESSONS
↓
GETTING A CERTIFICATE

PROOF changes the model to:

LEARN
↓
PRACTICE
↓
PROVE
↓
EARN
↓
WORK
↓
TEACH
↓
EARN MORE

The fundamental idea:

> Don't tell people you know something.
> Prove it.

A user should be able to say:

"I want to learn Python."

PROOF creates a learning path.

The user studies.

The AI teaches them.

The user completes practical challenges.

The AI evaluates their work.

Their skill profile evolves.

They earn NIM for completing eligible challenges.

Once they demonstrate sufficient ability, they can use their verified skill to apply for paid tasks.

---

# 2. IMPORTANT PRODUCT PRINCIPLE

DO NOT build a generic online course platform.

DO NOT build:

* Udemy clone
* Coursera clone
* Khan Academy clone
* "watch videos and earn tokens"
* generic AI chatbot
* crypto certificate platform

The differentiating mechanic is:

# PROOF OF SKILL

Learning only matters when the user can demonstrate competence.

# 11. AI EVALUATION SAFETY

AI grading must NOT be the sole source of truth for high-value rewards.

For MVP:

Use AI evaluation for learning feedback.

For reward eligibility:

require additional safeguards such as:

* minimum challenge completion
* server-side validation
* anti-cheating checks
* rate limits
* deterministic checks where possible
* human verification for high-value challenges

Never allow a client to tell the server:

"I scored 100."

The server must determine the result.

# 20. ANTI-CHEATING

Implement basic protection.

Users should not be able to:

* submit unlimited attempts instantly
* repeatedly farm rewards
* manipulate scores
* duplicate challenge rewards
* modify XP client-side
* modify NIM reward values
* claim the same reward multiple times

Use:

* server-side challenge IDs
* attempt IDs
* completion records
* unique constraints
* rate limits
* timestamps
* reward transaction records

For coding challenges, use sandboxed execution where appropriate.

Never execute arbitrary user code directly on the API server.

---

# 21. WALLET INTEGRATION

Integrate with the official Nimiq Mini Apps environment.

Before implementing wallet functionality:

1. Inspect the current official Nimiq Mini Apps documentation.
2. Identify the currently supported wallet/provider APIs.
3. Identify transaction APIs.
4. Identify signing/authentication capabilities.
5. Use the current official APIs rather than inventing APIs.

Create:

WalletService

with:

connect()

disconnect()

getAddress()

getBalance()

sendNim()

signMessage()

onAccountChange()

Wallet functionality must be isolated from the UI.

Never scatter blockchain logic across components.

---

# 22. WALLET AUTHENTICATION

Where appropriate:

1. User connects wallet.
2. Server generates nonce.
3. User signs nonce.
4. Server verifies signature.
5. Server creates authenticated session.

Never use the wallet address alone as sufficient proof of ownership for sensitive operations.

Never request seed phrases or private keys.
