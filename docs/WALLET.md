# WALLET — Nimiq integration

## Official environment (verified against nimiq.dev, Aug 2026)

Mini apps run **inside Nimiq Pay** (WebView) and talk to the wallet through an injected provider. The recommended access pattern is the official SDK:

```js
import { init } from '@nimiq/mini-app-sdk'
const nimiq = await init()

await nimiq.listAccounts()        // → ['NQ… … …']  (user-confirmed)
await nimiq.sign(message)         // → { publicKey, signature }  (hex strings)
await nimiq.sendBasicTransaction({ recipient, value /* luna */, fee?, validityStartHeight? })
await nimiq.sendBasicTransactionWithData({ recipient, value, data })
await nimiq.isConsensusEstablished()
await nimiq.getBlockNumber()
```

Also available to mini apps: `requestDeviceIdentifier({ reason })` (anti-spam/leaderboards) and `window.nimiqPay.language`.

## WalletService — one boundary, three modes

`web/js/wallet.js` is the **only** module with blockchain logic (spec §21). UI calls its methods; nothing else imports a provider.

```js
WalletService.connectNimiqPay()  // in Nimiq Pay: SDK init → listAccounts → sign-in challenge
WalletService.connectNimiqHub()  // desktop browsers: Nimiq Hub popup (Accounts Manager)
WalletService.connectDemo()      // clearly-labeled demo wallet (real Ed25519)
WalletService.sendNim({recipient, nim, note})  // → sendBasicTransaction(WithData) → tx hash
WalletService.signMessage(msg)
WalletService.disconnect()
```

The connect sheet picks the right default for the device (`isDesktopLike()`): **Nimiq Hub on desktop browsers, Nimiq Pay inside the mini app**, demo always available as third option.

### Desktop: Nimiq Hub (Accounts Manager)

Outside Nimiq Pay, desktop users connect through the official **Nimiq Hub** (`@nimiq/accounts-client@0.4`, loaded from CDN at connect time):

```js
const client = new AccountsClient('https://hub.nimiq.com/');   // mainnet hub
const account  = await client.login({ appName: 'PROOF' });          // secure popup
const { nonce, message } = await api.post('/api/auth/nonce', { subject: account.address });
const signed   = await client.signMessage({ appName: 'PROOF', message, signer: account.address });
// signed → { signer, signerPublicKey: Uint8Array, signature: Uint8Array } → hex → verify
```

The Hub signs with the exact scheme our server verifies — `sha256('\x16Nimiq Signed Message:\n' + length + message)` over Ed25519 — so the same `/api/auth/verify` path serves Nimiq Pay and Hub sessions. Payments (`sendNim`) remain a Nimiq Pay capability; on desktop, rewards accumulate in the app ledger and payout requests are recorded for settlement.

### Server twin

`server/services/wallet.js` + `server/auth.js` verify what the client claims:

- **Nonce challenge** (`POST /api/auth/nonce`) — single-use, 10-minute TTL.
- **Signature verification** — Nimiq signed-message format:
  `sha256('\x16Nimiq Signed Message:\n' + byteLength + message)` verified as **Ed25519** via `node:crypto` (raw 32-byte keys wrapped in SPKI). A wallet address alone never authenticates anything.
- **Balances/chain reads** — `NIMIQ_RPC_URL` enables JSON-RPC reads; without it, the UI shows the in-app ledger balance and says so.
- **Payouts** — demo mode records a `pending → confirmed` ledger tx explicitly labeled "demo ledger"; production mode sends from the treasury and stores the on-chain hash as the transaction `ref`.

### Demo mode — what's real and what isn't

| Real | Simulated (labeled) |
|---|---|
| Ed25519 key generation | On-chain txs (no RPC/treasury in sandbox) |
| Signature challenge→verify auth | NIM price feeds (none used) |
| Reward ledger, caps, fees, escrow | Treasury settlement timing |

The demo keypair is generated by the server, handed to the client for the session, and every screen labels it `🧪 Demo wallet`. No seed phrases or private keys are ever requested from users (spec §22).

## Transaction safety (spec §63)

Every money movement is a `wallet_tx` row: `{ status: pending | confirmed | failed | cancelled, network, ref, note }`. The UI never says "you received NIM" before the tx is confirmed *in the app's transaction model* — see `RewardService` and `tests/economy.test.js`.
